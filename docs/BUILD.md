# Build

The sole default product line is **Hybrid**: SQ1/SQ2 share Linux `6.18.60-sq2-android1`, Mesa GLES/Turnip + QTI gralloc/mapper5/HWC + native OMX. See [DEVELOPMENT](DEVELOPMENT.md) for general delivery rules.

## 1. Entrypoint

Built-in audio applies `prepare-sq2-primary-audio.py` by default after runtime library replacement: 48 kHz PRIMARY uses 10 ms frame writes, and the physical playback proxy retains at least a 5760-frame buffer request. Input is a microphone-fixed donor HAL; reusing an already-fixed version skips re-patching, and unknown inputs fail explicitly at build time. See [Internal Speakers](SPEAKER-LOUDNESS.md) for boundaries.

```sh
python3 scripts/build.py --private-root PREPARED_INPUTS --output FRESH_LINUX_OUTPUT
```

- Omitting the subcommand defaults to `full-image`; `--graphics` only accepts `hybrid`.
- A slim 5-partition layout is enabled by default (`super` packs active `_a` EROFS slices only, `metadata`, `misc`, `SQ2PROBE` 1 GiB, `userdata`; default disk size `8 GiB`, adjustable via `--size-gib` / `--esp-mib`); pass `--preserve-template-layout` to fall back to the 39-partition `20 GiB` template layout.
- `compile` builds kernel components only; `verify`/`package` verify/copy the legacy pinned package; `--esp-only` outputs only the boot partition.
- Output must be a fresh directory on a Linux filesystem; do not run source builds directly on NTFS/9p.
- Dependency preparation runs on an original SQ1/SQ2 Windows installation; see [DEPENDENCIES](DEPENDENCIES.md).
- Boot origin EFI is built from GNU-EFI source: prepare [the matching revision](https://github.com/ncroxon/gnu-efi/tree/aeee48d838d40e8ef787748d5dc066ea2fb99dbe) at `PRIVATE_ROOT/kernel-6.18/gnu-efi`, or pass `--boot-gnu-efi DIR`. The Linux host requires `patchelf`, `make`, and AArch64 GCC/binutils supporting `efi-app-aarch64`.
- Reusing or specifying a prebuilt kernel requires `patches/spx-portable-boot/` fixes and matching modules; the boot ESP must be writable to record the boot origin.

## 2. Private Inputs

Default root `private/build-inputs/` (relocatable via `--private-root`):

```text
template.img                       # Original 20 GiB layout template, unmodified
kernel-6.18/
  source/SOURCE.json, source.tar.gz
  toolchain.tar.gz, board.dts, firmware/, EFI/
full-image-runtime/
  INPUTS.json, records.json, files/
camera/CAMERA.json + ELF
sensors/sensors-bundle.json + files
suspend/desktop-services.jar       # Patched at build time for AC screen-off timeout
typec/services.jar                 # Shared Android JAR, fixes unknown lid state
```

Component input sources:

| Component | Preparation | Notes |
| --- | --- | --- |
| Camera | `scripts/build-spx-camera-bundle.py --inputs private/camera-build.json` | Built from source; requires matching AIDL/platform headers/libs, see [CAMERA-BUILD](CAMERA-BUILD.md) |
| Sensors | `scripts/build-spx-sensor-bundle.py` | ALS/accelerometer/SLPI/RPC/overlay, see [SENSORS](SENSORS.md) |
| Type-C / Multi-display / ADB | Default `full_image_typec.py`, rebuilds matching modules from source + native Settings entry | Shared `services.jar` and Java/smali/SDK tools, see [TYPEC](TYPEC.md) |
| Suspend | `scripts/full_image_suspend.py --desktop-services ... --output private/build-inputs/suspend` | Original JAR from the same Android system, see [SUSPEND](SUSPEND.md) |

Missing inputs fail explicitly; do not bypass ABI/pairing checks by altering version numbers or reusing old modules.

## 3. Build Order

```text
Shared platform dependencies + matching 6.18 kernel build tree
 ├─ Camera source → driver/AIDL/HAL/ISP/mapper/allocator → camera/CAMERA.json
 └─ Sensor source + shared OEM assets → modules/SubHal/overlay/RPC/SLPI EFI → sensors-bundle.json
                                   ↓
full-image: prepare kernel source → display/A6xx patches → Image/modules/DTB → out-of-tree modules/depmod
                                   ↓
Rebuild matching modules (or explicitly reuse components) → Hybrid graphics integration → touch wizard → install camera/sensors
                                   ↓
Venus suspend handshake + desktop-services.jar patch + one-time suspend settings migration
                                   ↓
Strip personal credentials / skip first-time setup → rebuild initramfs → pair EFI/SLPI firmware/device DT
                                   ↓
Template system partitions + fresh userdata/metadata → GPT/ESP/filesystem readback → IMG/IMG.GZ/manifests
```

Camera and sensor bundles must be prepared before the full kernel build.

## 4. Reusing Completed Components

```sh
python3 scripts/build.py --private-root PREPARED_INPUTS --reuse-components REUSE.json --output FRESH_LINUX_OUTPUT --jobs 8
```

The reuse manifest is generated by `full_image_reuse.py` with explicit hashes; it reuses Image/all modules, camera, sensors, Mesa, and glue while still performing full disk assembly and verification. When only the touch wizard Java/Manifest changes, the old APK is automatically invalidated and rebuilt.

When only Venus needs refreshing, rebuild it first before reusing:

```sh
python3 scripts/rebuild-hybrid-venus.py --reuse-components PREV_REUSE.json \
  --kernel-build MATCHED_KOUT --source PREV_VENUS_SOURCE --output FRESH_VENUS_OUTPUT
python3 scripts/build.py --reuse-components FRESH_VENUS_OUTPUT/REUSE.json \
  --private-root PREPARED_INPUTS --output FRESH_IMAGE_OUTPUT
```

## 6. First Boot and Privacy

After Android finishes booting and the current user is user 0, `surface-first-boot` sets `device_provisioned=1` / `user_setup_complete=1`, disables installed setup wizards, and launches HOME; on success it writes `/data/system/surface-first-boot-v1`, otherwise it retries next boot.

The image strips inherited accounts, Wi-Fi, and SSH credentials, locks root, disables SSH by default, and uses fresh userdata/metadata without disabling captive portal detection or pre-provisioning networks. Skipping Android first-time setup does not skip the standalone touch calibration wizard. See [IMAGE](IMAGE.md) for details.

### Hybrid Source Build: QCOM Submission Optimization

Default source builds append MSM shared submission patches and GPUVM reservation v2 patches to the Adreno patch series. QCOM userspace is built from repository source and the GSL donor in private inputs, requiring Android NDK AArch64 API 35 clang (configurable via `SQ2_ANDROID_CC`), `readelf`, and `patchelf` supporting `--rename-dynamic-symbols`.

Hybrid continues to use Mesa GLES/Turnip, QTI gralloc/mapper5/HWC, and native OMX. Regular apps opening MSM via QCOM/GSL enable `VM_BIND` by default; system, isolated, and SDK sandbox UIDs are excluded. BO sharing policy remains `exclude`, reusing sync preparation templates when handle, access flags, queue, and sharing state match while re-collecting fences per submission.

### OMX Low-Latency Remote Control

The bridge maps `LOWLATENCY_MODE` to Venus zero-display-latency control. When decoding has not started, OMX warm-up stop returns only VB2 buffers held by software without sending FLUSH to an unstarted firmware session; active sessions still wait for real HFI confirmation. Updates require rebuilding and packaging the bridge library and paired `venus-dec.ko`.

## 7. Boundaries

### Advanced Settings: Vulkan Configuration, Performance Mode, and Touch

The Hybrid full image builds and installs `SurfaceAdvancedControl.apk` from `probe/advanced-control/` and integrates `/bin/spx-advanced-control-boot` into initramfs, switching UI strings automatically between Chinese and English.

- **Top-level selection page**: Includes **Vulkan Configuration**, **Performance Mode**, and **Touch**.
- **Vulkan Configuration**: Supports changing global default policy (Auto Policy / MESA / Qcom in `persist.sq2.vulkan.driver`; system UIDs `< 10000` and `com.android.systemui` remain forced onto Mesa Turnip) and per-app overrides (`persist.sq2.vulkan.app.<user>.<package>`, overridden apps pinned to top); environment/boot overrides, rescue mode, and Zygote protection take precedence, and changes apply on next app launch.
- **Performance Mode**: Dynamically reads governors commonly supported across all cpufreq policy domains, applying via the built-in root bridge and persisting to `/data/vendor/spx-advanced-control/cpu_governor` for automatic restore on boot (skipped in rescue mode or `sq2.cpufreq=0`); hardware thermal protection remains enabled.
- **Touch**: Provides a **Ghost-Touch Patch** master toggle (preserving `.noise` samples and writing `.noise.disabled` while clearing `/run/iptsd-noise/active` and reloading `iptsd`), current calibration summary, **Recalibrate** (`org.surface.touchcalibration.unified`), **Export Calibration Data** (`.spkcal`), **Apply Calibration from File**, and **Clear Calibration Data**.

Build APK standalone: `python3 scripts/full_image_advanced_control.py --output OUTPUT/SurfaceAdvancedControl.apk`. Signing keystore is at `private/advanced-control/signing.keystore` (or via `SPX_ADVANCED_CONTROL_KEYSTORE`). Reuse builds recompile the Vulkan router, Advanced Settings APK, and refresh bridge scripts.

### Rescue Mode (`spx-rescue` / `sq2.rescue=1`)

The default kernel enables `r8152` (built-in) and `usbnet` / `ax88179_178a` / `cdc_ether` / `cdc_ncm` / `rndis_host` (modules), with rescue components integrated in initramfs (`scripts/full_image_rescue.py`, `probe/rescue/`):

- **Halts before Android init**: After discovering the boot disk and `/media/esp`, stays in the rescue console before mounting Android partitions or starting `/system/bin/init`.
- **SSH (Rescue Mode only)**: Starts Dropbear (port 22) allowing public keys (`/root/.ssh/authorized_keys`, auto-importing `/media/esp/rescue/authorized_keys` or `/media/esp/authorized_keys`) and rescue-only in-memory default password `000000`.
- **USB NIC & Wi-Fi TUI**: Loads attached USB NICs with DHCP, brings up `wifi-services`, `ath10k_snoc`, and `wpa_supplicant`, provides static ARM64 `/bin/spx-wifi-tui` for Wi-Fi connection and live network/SSH status, and offers `spx-rescue-usb-gadget start|stop` for lower-port USB NCM gadget mode.
- **Continue booting Android**: Running `start-android` (alias `continue-android`, or `b` in `wifi-tui`; supports `--safe` / `--stop-ssh` / `--umount`) runs `spx-rescue-handoff` to tear down rescue networking/gadget, restore normal boot parameters, and execute `exec native-handoff /newroot`.

### System Update (OTA) and Update Package Build

- **Full builds produce OTA packages by default**: `python3 scripts/build.py --output FRESH_OUTPUT` invokes `scripts/build_ota_package.py` after `disk/` to generate `FRESH_OUTPUT/ota/` (supports `--ota-mode auto|delta|esp|full`, `--ota-baseline PREV_BUILD_OR_MANIFEST`, `--ota-version VER`, `--skip-ota`).
- **Build standalone**: `python3 scripts/build.py ota --build-output BUILD_OUT [--previous-manifest PREV/ota/OTA-MANIFEST.json] --output OTA_OUT`.
- **Automatic slimming**: In `auto` mode, if `super` is unchanged, only deduplicated updated files and manifests (`ota-manifest.json`, `ota-manifest.kv`, `ota-files.tsv`) are packed without `super.img`; `--previous-manifest` packs only changed/added files plus `DEL` entries; when `super` changes or `--mode full` is used, `payload/super.img` is included.
- **On-device update service**: `SurfaceAdvancedControl.apk` includes `SystemUpdateActivity` (`android.settings.SYSTEM_UPDATE_SETTINGS`), and `/bin/spx-ota-boot` disables conflicting update pages on boot. Supports manifest `.tar.gz` (online ESP write when `super` is unchanged and data is kept; otherwise initramfs offline stage) and full `.img` / `.img.gz` (handled by `/bin/spx-ota-stage` and `/bin/spx-ota-tool` before mounting), both allowing data preservation or wiping `userdata`/`metadata`/`misc` for a clean install.
- **One-click ADB upgrade**: Windows uses `tools/Upgrade-GooglebookViaAdb.ps1` (or `.cmd`), Linux/macOS uses `sh tools/upgrade-googlebook-via-adb.sh -p <package> [--wipe-data]`, verifying compatibility and free space, backing up `EFI/SQ2Nat`, and triggering a two-stage reboot for offline update.
- **Install to Internal Disk (Clean install from USB)**: `InternalDiskInstallActivity` invokes `/bin/spx-internal-install` and `/bin/spx-ota-tool` via `/bin/spx-ota-boot`. Enabled only when booted from USB with a standard 5-partition source and a sufficiently large internal non-USB disk; rebuilds a fresh 5-partition GPT, streams and SHA-256-verifies `super`, writes standalone `EFI/BOOT/grub.cfg`, formats `metadata`/`userdata`/`SQ2PROBE`, and prompts to power off and unplug USB before cold-booting.

### Full-Disk Acceptance Boundaries

- Default builds produce artifacts only without running test suites, full-disk decompression checks, or SHA manifests; compile errors and format/ABI/pairing constraints still abort the build.
- Proprietary libraries and firmware are distributed under their respective licenses; see [PROVENANCE](PROVENANCE.md) for sources and [STANDARD-BUILD](STANDARD-BUILD.md) for full pipeline details.
